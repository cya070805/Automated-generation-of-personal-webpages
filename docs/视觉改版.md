# 视觉改版说明（2026-11）

## 上一版的问题

第一版跑通流程之后，页面长这样：一栏 680px 的正文，姓名 34px，正文 14.5px，
关于 / 经历 / 项目 / 技能 全都是同一段 14px 的文字，六套基底的区别只有底色和字体。

三个具体毛病：

1. **字阶是平的**。姓名 34px、正文 14.5px，比例 2.3:1。杂志是 8:1 左右。比例不拉开，
   页面就没有「第一眼」，读起来像 Markdown 简历。
2. **只有一栏**。1440 的屏幕上正文占 680px，右边 700px 全是空的，没有栏目标题栏、
   没有编号、没有分隔，眼睛落不到任何东西上。
3. **六套基底只是换色**。同样的组件、同样的堆叠，换个 bg 和 font 就叫一套新模板——
   那不叫模板，叫主题。

## 这一版改了什么

### 1. 字阶拉开到 7:1

```
--b-size-display   clamp(52px, 8vw, 104px)   首屏姓名
--b-size-title     17–21px                   项目名、公司名
--b-size-lead      16–19px                   一句话定位、摘要
--b-size-body      14–15px                   正文
--b-size-meta      10.5–11.5px               页眉、章节名、日期
```

每套基底自己定这六档，但比例是共用的。正文行宽仍然限在 40–52 个中文字
（`--b-measure`），宽画布不牺牲可读性。

### 2. 页面有了骨架

```
页眉（细线 + 名字 + 年份）
首屏（姓名 / 定位 / 身份图形 / 邮箱·城市·现在）
────────────────────────────
01 关于   │ 正文
────────────────────────────
02 实习   │ 条目
────────────────────────────
03 项目   │ 条目
────────────────────────────
04 教育   │ 条目
────────────────────────────
05 技能   │ 一行
────────────────────────────
收尾（联系方式）
```

章节是 `grid-template-columns: var(--b-rail) 1fr` 两栏：左栏放编号和章节名，
用 `position: sticky` 跟着滚；右栏放正文。窄屏塌成单栏，编号缩到行首。

页宽从 680 提到 1080–1240，但正文仍然窄——宽的是「画布」，不是「行」。

### 3. 六套基底各有各的页框

新增 `rhythm.frame`，它决定页眉和章节分隔怎么做，这是六套之间最大的差别：

| frame | 谁用 | 长什么样 |
| --- | --- | --- |
| `rule` | Paper | 通栏细线页眉，章节用细线 + 大号灰编号 |
| `chrome` | Terminal | 窗口栏（三个圆点 + 路径），章节记号是 `##` |
| `masthead` | Editorial | 报头 `VOL. 01`，粗细双线，章节号是红色 `01` |
| `none` | Gallery | 不画线，只留极小的行首标签，页面几乎全宽 |
| `grid` | Studio | 可见网格底纹 + 顶部状态条，深色 |
| `tile` | Bento | 首屏就是一格一格的卡，正文区沿用同一套圆角 |

首屏也按基底给了六种排法：`column / prompt / masthead / plate / split / bento`，
分别对应上面六套。

### 4. 身份图形

用户还没传头像，页面不能空着。`components/render/identity-mark.tsx` 按姓名算一个
确定的图形（FNV-1a 哈希 → 图案、角度、偏移），同一个名字永远长同一样，
换基底跟着换色。输出是纯 SVG，导出包里不依赖任何外部图片。

以后接了真实头像，把这个组件换成 `<img>` 就行，位置和比例不用动。

### 5. 动效

章节用 `Reveal`（IntersectionObserver + `prefers-reduced-motion` 兜底）滚动淡入；
Terminal 的标题用打字机；首屏不做动画，第一眼要立刻看到名字。

### 6. 打印

`toPrintBase()` 仍然把所有基底翻成白纸黑字，但**保留页框**：
`chrome` 和 `grid` 降级成 `rule`，`masthead` 的双线保留。
所以 PDF 有章节线、有编号、有页眉，不是一张裸文本。

## 怎么加一套新基底

1. 在 `src/lib/templates/types.ts` 的 `BaseId` 里加一个 id；
2. 在 `bases.ts` 的 `BASES` 里加一份令牌：颜色、字体、六档字号、页宽/栏宽、
   `rhythm.frame` 和 `rhythm.hero`；
3. 在 `recipes.ts` 的 `DEFAULT_RECIPE_MAP` 里给它挑一套默认讲法；
4. 如果 `frame` 也是新的，在 `globals.css` 里加一段 `[data-base="新id"]` 的样式。

不需要动渲染层——`site-view.tsx` 只读令牌，不认基底名。

## 没解决的

- 真实图片仍然没有上传入口，Gallery 现在是「大字清单 + 海报纸」的降级形态；
- 首屏的身份图形是程序生成的，不是照片；
- 移动端只做了不塌（420px 验过），没做专门的手机版式。
