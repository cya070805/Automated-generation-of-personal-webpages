## 02 章的三层结构

- **基底 6 套**：Paper / Terminal / Editorial / Gallery / Studio / Bento，纯令牌。
- **原语 12 个**：八个纯 CSS + 四个客户端岛，全部遵守 `prefers-reduced-motion`。
- **配方 21 条**：页面只存 `{ slot: recipeId }`，不兼容或缺失自动回落到基底默认。

## 03 章的关键约束

| 约束 | 落地方式 |
| --- | --- |
| render 不读数据库 | `components/render` 只收 `SiteData` + 令牌 |
| 模板只消费设计令牌 | 所有槽位只用 `var(--b-*)`，没有一个硬编码色值 |
| 编辑态 / 托管页 / 导出包同一套组件 | `/preview`、`/p/[slug]`、导出的 HTML 都来自 `SiteView` |
| PDF 与页面同源 | Playwright 打印 `/preview?print=1`，不二次排版 |
| Key 不入库 | 只在 localStorage 与请求头 |

## 没做的，以及为什么

1. **自由模式（元素级拖拽）**。方案 3.5 要求「绝对定位 + 8pt 网格 + 12 列参考线」，
   这本质是重做一个画布引擎。现在的替代是**槽位级**的自由：能排序、能隐藏、能换讲法、能改字。
   要真做，需要 dnd-kit + 一套 layout JSON schema，属于下一个迭代。
2. **AI 自动推荐基底**。方案 2.5 说「AI 直接给三个成品」。现在通过 `baseId + recipeMap`
   已经具备渲染三个候选的能力，缺的是一次「按内容挑 3 组」的模型调用。
3. **动态部署包（Node 运行时后台）**。导出包里给了 Node 静态服务器与 Docker，
   但没有包内后台——方案里「包内后台改，或重新导出覆盖」，现在只支持后者（重新导出覆盖）。
4. **头像与作品图**。`assets` 表在，上传与裁切没做，所以 Gallery 目前是「无图降级」形态。

## 已知取舍

- 深色基底导出 PDF 时会切成白底黑字（`toPrintBase`），不保留暗色背景。
- 导出 HTML 内联的是整份 Tailwind，约 40KB，单文件换来零依赖。
- 编辑器的预览是 iframe 重载，不是增量热更新；保存 300ms 防抖。
