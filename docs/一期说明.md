# 一期交付与核对

对照 `docs/build/产品能力地图与技术方案.docx`（v2.0，2026.11）核了一遍。

## 一期的三件事

方案 3.8：**一期 = 骨架 + 数据模型 + 模型接入**。

| 要求 | 现状 | 结论 |
| --- | --- | --- |
| 应用骨架：Next.js 15 + TS，页面与路由能跑 | `/` `/start` `/edit/[token]` `/preview/[token]` `/settings` 全部 200 | 一致 |
| 数据模型：十张表，`pages` 记 `base_id` / `recipe_map` | 十张表齐全；`pages` 缺 `baseId` / `recipeMap` | **不一致，已修** |
| 模型接入：五家预设 + Key 只在前端 + 同源转发 | DeepSeek / 通义 / 智谱 / Kimi / OpenAI + 自定义；`/api/llm/chat` 转发 | 一致 |
| 架构约束：`render` 不读数据库、模板只消费设计令牌 | 渲染层只收 `SiteData` + 令牌；页面里不出现硬编码色值 | 二期建立，已达标 |

### 修了什么

`pages` 表按方案表 14 补了两列：

```prisma
baseId    String  @default("paper")  // 基底：只决定气质
recipeMap Json?                       // 各槽位用哪条配方
```

迁移 `20261111125144_page_base_and_recipe`，并把老数据从 `theme.preset` 回填到 `baseId`。

## 与方案顺序的偏差（有意为之）

方案把「内容闭环」排在**三期**，代码里已经做完（解析 → 追问 → 两版文案）。
原因是二期要验证渲染层，总得先有内容喂进去。这不影响一期的验收口径：
一期验的是骨架、表、模型接入，这三项都过。

## 没做的（属于后续期）

- 平台发布 `/p/[slug]`、部署包导出（四期）
- 配方库首批 20 个（三期）——现在只有 15 条人工种子
- PDF 导出（四期）
